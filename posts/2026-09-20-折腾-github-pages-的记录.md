一直想有个自己的小角落，能写点东西。试过几个平台，最后还是觉得 **GitHub Pages** 最合心意：免费、干净、域名好看（`名字.github.io`），而且所有内容都是自己的文件，不怕哪天平台关门。

## 为什么选 GitHub Pages

对比了一下常见的几种方案：

| 方案 | 优点 | 顾虑 |
| --- | --- | --- |
| 博客平台（掘金、知乎） | 有流量、不用维护 | 排版受限，不像"自己的地方" |
| 云服务器 + 博客程序 | 想怎么改就怎么改 | 要买服务器、要维护、要备案 |
| GitHub Pages | 免费、纯静态、域名固定 | 只能放静态页面 |

对我来说，写博客主要是为了**记录和整理**，不需要太多花哨功能，所以 GitHub Pages 刚好。

## 动手的过程

1. 注册 GitHub 账号，用户名决定了域名，所以当时纠结了很久叫啥 🙈
2. 新建一个仓库，名字必须是 `用户名.github.io`，这样才是主页
3. 往仓库里放一个 `index.html`
4. 等一两分钟，访问 `https://用户名.github.io` 就能看到了

最开始的 `index.html` 是手写的，长得比较朴素，但看到自己的网页出现在互联网上，还是有点小激动。

## 遇到的小坑

### 1. 改完文件要等一会儿

GitHub Pages 不是实时生效的，推上去之后要等构建完成（一般几十秒到一两分钟）。第一次改完刷新没变化，我还以为改错了。

### 2. 文章点不进去

一开始我把文章标题写成链接放在首页，但链接指向的是 `#`，点进去什么也没有——因为那些文章页面其实**根本不存在**。

> 教训：静态网站里，每一个页面都得是真实存在的文件。首页写了个标题不等于文章就有了。

### 3. 路径的大小写

Linux 服务器区分大小写，`Image.png` 和 `image.png` 是两个不同的文件。本地 Windows 上看着没问题，传上去就 404 了。

## 后来用上的命令

本地预览和构建的时候会用到这几个：

```bash
# 构建整站
node build.js

# 本地起个服务预览
node serve.js
```

推送更新：

```bash
git add .
git commit -m "写文章"
git push
```

## 小结

搭站本身不难，难的是**坚持写**。所以这次我特意把发布流程做得特别短：写完 Markdown，上传，剩下的事情交给自动构建。

希望这个小站能一直更新下去 ✍️
